状态：**规划未实现**。本文件仅登记作者 2026-10-01 决定的部署配置 Skill 方案，供后续任务实现与验收；当前不存在任何已实现/已安装的配置 Skill，本文件本身不修改任何本机 AGENTS、CLI 配置或打包清单。管理任务：`019fe10b-df55-7b82-a9ba-3702dc08c55f`；冻结基线：`a03bbb91fa18fed4492fcc17a85a40601700ee44`。

## 1. 目标与运行时机

- 该 Skill 的职责：在本机为新启用或新增的 Bridge（如 Cursor CLI，后续按作者批准扩展）做**部署配置登记与核验**——发现宿主 Shell/依赖、生成或更新指令文件改动预览、经用户确认后写入。
- 运行时机：**Skill 部署完成后首次运行**，以及**每次新增 Bridge 时**按需运行。它与日常 bridge 调用 Skill 分离：安装/配置一次，日常调用走薄入口。
- 详细度：配置 Skill 可以详细——不为给自身省 token 而牺牲可靠性；省 token 的责任由三层薄化承担（见 §3）。

## 2. 流程记录（实现时的固定步骤）

1. **询问启用哪些 Bridge**：先问用户本次要启用/新增哪几个 Bridge，只处理所选；未选择的 Bridge 一律不写任何内容。
2. **只读核验环境**：核验 Windows 版本、可用 Shell、PowerShell 7（`pwsh`）是否存在及其入口路径。只读探测，不做任何写入。
3. **安装建议优先**：若 `pwsh` 7 缺失，**优先建议用户安装 PowerShell 7**（按官方渠道），而不是擅自改 `PATH` 或代为安装；用户明确授权前不改主机配置。
4. **各厂商遵从官方建议 + Windows 实测**：每个 Bridge 的启动方式以其官方文档为首选依据，并在本机 Windows 实测确认；**区分“启动 CLI 的 Shell”与“Worker 执行命令的 Shell”**（两者可能不同，逐项记录，不混写）。
5. **无验证不自动降级**：当前产品 runner 依赖 pwsh 7（ACL 辅助、Cursor 固定入口）；未经验证不得自动改用其他 Shell 或放宽要求。降级只在兼容表中有实测依据且用户确认后进行。
6. **生成改动预览 → 用户确认 → 写入**：任何对指令文件的写入必须先展示完整预览（新增/修改的管理区块、保留的原文范围），经用户确认后落盘。

## 3. 三层薄化与去重原则（长期写入形态）

长期把配置结果写入三处时，各自职责严格分层、互不复制：

| 层 | 内容边界 |
| --- | --- |
| Codex 总 `AGENTS.md` | 只写：短入口（指向配置 Skill/兼容表）、已启用项清单、必要安全边界。不复制流程细节或管理流水线。 |
| 目标 CLI 总指令（如 Cursor 全局配置） | 只写：该宿主必要的补充（Shell/入口等已核验事实）。不复制产品管理流水线。 |
| 日常 bridge 调用 Skill | 保持简洁：常用命令与固定参数 + 按需参考链接；安装与调用分开，不在日常 Skill 里重复配置流程。 |

- 写入一律使用**可识别、可更新的管理区块**（带版本标记的注释围栏），更新时整块替换，避免追加式重复。
- 作用域优先级：**项目/任务级优先**；写入全局（用户级总指令）必须由用户明确选择，不默认全局。
- 每次写入保留原文并生成备份（原文完整可恢复），保证可回退。

## 5. 验收标准（实现任务的收口门禁）

1. **幂等**：重复运行同一配置不产生重复区块；再次生成常驻内容前先比较现状并去重。
2. **保留用户内容**：管理区块之外的任何用户原文逐字节保留；有备份且可回退到运行前状态。
3. **仅所选 Bridge**：未选择的 Bridge 无任何文件变化。
4. **未知不猜**：未知的宿主文件路径/配置位置不猜测、不写入；核验失败如实报“未核验”。
5. **预检不冒充实测**：无真实模型调用的预检不得表述为实测；预检与实测分别记录。
6. **预览-确认-写入**链路完整，无未经确认的静默写入。
7. 三层薄化边界（§3）与兼容表（§4）齐全，厂商未核验项标“待核验”。

## 6. 排序与边界

### 2026-10-02 补充：上游 CLI 更新兼容

- 尊重并允许厂商自动更新，必要时按官方方法手动更新；不要部署成默认禁用更新或永久钉死旧版本。日常调用 Skill 的按需排障说明见 `skills/local-agent-bridge/references/usage.md`，不复制到常驻 AGENTS。
- 配置兼容表补充各 CLI 的版本探测、更新入口与实际后端定位方式，只登记核验事实。GUI/CLI/SDK 分开，不推定同步升级；维护步骤不在活动作业中替换安装。
- 产品后续检查实际版本可观测性与异常变化适配：入口/后端版本、模型目录和输出结构变化的诊断应有据可查；先核对现有能力再补最小缺口，不建更新服务或定时轮询。版本改变本身不等于失败，未知合同变化也不算成功。
- 用离线用例覆盖入口不变后端变化、旧参数不支持、模型不存在与订阅拒绝的区分、输出结构变化；若版本探测失败保留原始失败类别，不进入重试循环。涉及产品行为变更须另行实现与验证，本补充仅为规划。
